# Proposal

## Why

질문은 앱이 사용자 PC에 설치된 Claude Code나 Codex CLI를 실행해서 보냅니다. 그러려면 고른 에이전트가 그 실행 환경에서 로그인되어 있어야 합니다. 그런데 지금 시작 설정 창은 로그인 여부를 확인하지 않아서, 로그인하지 않은 사용자도 설정을 마치고 넘어갑니다. 이 사용자는 질문을 보낸 뒤에야 실패를 알게 됩니다.

Anthropic의 Claude Code 약관("Authentication and credential use")은 서드파티 앱이 자기 앱에서 Claude.ai 로그인을 제공하거나 자격 증명과 세션 토큰을 다루는 것을 금지합니다. 최종 사용자가 수정하지 않은 Claude Code에 자기 구독으로 로그인하는 것은 허용합니다. 그래서 앱은 로그인을 대신 실행하지 않습니다. 로그인 상태만 CLI에 묻고, 로그인은 사용자가 터미널에서 직접 하도록 안내합니다(OpenCode의 Claude Agent provider와 같은 방식).

그리고 지금은 감지, 훅 설치, 선택이 한 화면에 모두 펼쳐져 있습니다. 단계가 하나 더 늘면 화면이 길어지고, 지금 무엇을 해야 하는지 알기 어려워집니다.

## What Changes

- 앱이 고른 에이전트와 실행 환경의 로그인 상태를 확인합니다. Claude Code는 `claude auth status`, Codex는 `codex login status`로 CLI에 묻습니다. 앱은 CLI가 저장한 로그인 파일, Keychain, 토큰을 직접 읽지 않습니다.
- 로그인 상태 확인은 모델을 호출하지 않아 사용 토큰을 쓰지 않습니다. WSL 항목은 그 배포판 안의 CLI로 확인합니다.
- 로그인되어 있지 않으면 시작 설정 창에 터미널에서 실행할 로그인 명령(`claude auth login`, `codex login`)과 복사 버튼, 다시 확인 버튼을 보여 줍니다. 앱은 로그인 명령을 실행하지 않습니다.
- 시작 설정 창을 스테퍼로 바꿉니다. 한 번에 한 단계만 보여 주고, 이전과 다음 버튼으로 단계를 오갑니다. 단계는 감지, 훅 설치, 에이전트와 모델 선택, 로그인 확인 순서입니다.
- 지금 단계에서 넘어갈 조건이 채워지지 않으면 다음 버튼을, 돌아갈 단계가 없거나 돌아가면 안 되는 상황(감지 진행 중 등)이면 이전 버튼을 비활성화합니다. 마지막 단계의 다음 버튼은 지금의 다음 버튼처럼 선택을 보관하고 작은 창으로 넘어갑니다.
- 단계마다 그 단계의 일을 다시 하는 버튼을 둡니다. 감지는 다시 감지(기존), 훅 설치는 다시 설치, 선택은 모델 목록 다시 불러오기, 로그인 확인은 다시 확인입니다.
- **BREAKING**(화면): 시작 설정 창이 세 단계를 한 화면에 함께 보여 주던 방식(FR-START-002)과, 에이전트와 모델만 고르면 넘어갈 수 있던 조건(FR-START-005)이 바뀝니다. 로그인되어 있지 않으면 작은 창으로 넘어갈 수 없습니다.

## Capabilities

### New Capabilities

없음

### Modified Capabilities

- `agent`: 설치된 에이전트의 로그인 상태를 실행 환경별로 확인하는 요구사항을 추가합니다.
- `start`: 시작 설정 창의 단계 표시를 스테퍼로 바꾸고(FR-START-002), 넘어가는 조건을 단계별 이전/다음 버튼 규칙으로 바꾸며(FR-START-005), 로그인 확인 단계와 선택 단계의 모델 목록 다시 불러오기를 추가합니다.
- `hook`: 훅 설치 단계에서 설치를 다시 하는 요구사항을 추가합니다.

## Impact

- `src-tauri`
  - 로그인 상태 확인 로직: CLI 출력을 로그인 상태로 해석하는 순수 로직과, 감지 결과의 실행 파일 경로(FR-AGENT-003)로 CLI를 실행하는 IO. WSL 실행과 macOS 로그인 셸 PATH(FR-AGENT-004)는 감지 쪽 코드를 다시 씁니다.
  - `commands/`에 로그인 상태 확인 명령을 추가하고, 결과 타입을 ts-rs로 내보냅니다.
- `src/renderer`
  - `api/`에 로그인 상태 확인 함수를 추가합니다.
  - `features/onboarding/`: 스테퍼 화면, 단계별 이전/다음 가능 여부를 정하는 순수 로직(`domain/`), 로그인 확인 단계 컴포넌트. 명령 복사에 클립보드를 쓰므로 필요하면 `onboarding` 창의 capability에 권한을 추가합니다.
- 다른 기능: 질문 보내기(다음 변경)는 이 단계를 통과한, 로그인된 에이전트만 받는다고 가정할 수 있습니다. 여러 계정 관리와 사용량 표시는 범위에 넣지 않습니다.
