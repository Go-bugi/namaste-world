### Q1. 감지와 훅 설치가 끝나면 다음 단계로 자동으로 넘어가나요?

- 근거: FR-START-002 "감지가 끝나도 자동으로 넘어가지 않음". 감지와 훅 설치는 사용자가 할 일이 없는 단계라서, 매번 다음 버튼을 눌러야 하는지에 따라 화면 흐름과 테스트가 달라집니다.
- 선택지: A. 자동으로 넘어가지 않음. 모든 단계를 다음 버튼으로 넘김 / B. 감지와 훅 설치는 끝나고 다음 조건이 채워지면 자동으로 다음 단계로 넘어감. 훅 설치가 실패하면 멈춤 / C. 감지와 훅 설치를 한 단계로 합침
- 권장: A. 감지 결과와 훅 설치 실패를 사용자가 확인하고 넘어가며, 이전 버튼으로 돌아왔을 때 다시 밀려 나가지 않습니다.

**답**: A. 자동으로 넘어가지 않고 모든 단계를 다음 버튼으로 넘깁니다. FR-START-002 그대로입니다.

### Q2. 로그인 확인이 "확인 실패"일 때 다음으로 넘어갈 수 있나요?

- 근거: FR-START-005 "로그인 안 됨" 시나리오, FR-AGENT-010. 확인 실패는 로그인 여부를 모르는 상태입니다. CLI가 오래되어 상태 명령이 없거나 일시적으로 응답하지 않으면 사용자가 이 단계에서 나갈 수 없게 됩니다.
- 선택지: A. 넘어갈 수 없음. 로그인됨일 때만 다음 버튼 활성화 / B. 확인 실패면 경고와 함께 다음 버튼 활성화. 로그인 안 됨일 때만 막음
- 권장: B. 훅 설치 실패를 넘어가게 둔 것(FR-START-005)과 같은 기준이고, 앱이 상태를 모른다는 이유로 사용자를 가두지 않습니다.

**답**: A. 넘어갈 수 없습니다. 로그인됨일 때만 다음 버튼을 활성화합니다(FR-START-005 그대로). 대신 단계마다 그 단계의 일을 다시 하는 버튼을 둡니다: 감지는 다시 감지(FR-AGENT-008), 훅 설치는 다시 설치(FR-HOOK-016 추가), 선택은 모델 목록 다시 불러오기(FR-START-010 추가), 로그인 확인은 다시 확인(FR-START-008). proposal의 Capabilities에 `hook`을 더했습니다.

### Q3. 로그인 확인 시간 상한은 몇 초인가요?

- 근거: SC-AGENT-002. WSL 항목은 배포판 안에서 로그인 셸을 거쳐 CLI를 실행합니다.
- 선택지: A. 5초 / B. 10초
- 권장: A. 모델 목록 조회(SC-START-001)와 같고, 고를 수 있는 WSL 항목은 이미 켜진 배포판이라 충분합니다.

**답**: A. 5초. SC-AGENT-002 그대로입니다.

### Q4. API 키나 클라우드(Bedrock, Vertex 등) 로그인도 "로그인됨"으로 보나요?

**답**: A. 로그인 방식과 상관없이 로그인됨입니다. FR-AGENT-009 그대로입니다.

### Q5. WSL 항목의 로그인 안내에서 복사하는 명령은 무엇인가요?

- 근거: FR-START-009 "WSL Codex 로그인 안 됨" 시나리오. Windows 터미널에서 바로 실행할 명령을 줄지, 배포판 안에서 실행할 명령을 줄지에 따라 문구와 테스트가 달라집니다.
- 선택지: A. 배포판 안에서 실행할 명령(`codex login`)과 "WSL `Ubuntu` 터미널에서 실행" 안내 / B. Windows 터미널에서 바로 실행할 명령(`wsl -d Ubuntu -- codex login`)
- 권장: A. B는 로그인 셸을 거치지 않아 nvm 등으로 설치한 CLI를 찾지 못할 수 있습니다.

**답**: A. 배포판 안에서 실행할 명령(`codex login`, `claude auth login`)을 복사하고, 그 배포판의 터미널에서 실행하라는 안내를 함께 보여 줍니다. 앱은 감지 결과로 WSL 항목과 배포판 이름을 압니다. FR-START-009 그대로입니다.
