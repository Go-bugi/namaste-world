# Proposal

## Why

캐릭터 반응과 성장은 Claude Code와 Codex가 지금 무엇을 하는지 알아야 만들 수 있습니다(`design/mvp-feature-decisions.md` 1절). 이 신호는 두 에이전트의 훅으로만 안정적으로 받을 수 있어서, 앱이 훅을 설치하고 훅이 보낸 이벤트를 받는 통로부터 만들어야 합니다.

## What Changes

- 앱이 `127.0.0.1`에 로컬 HTTP 서버를 열어 훅 이벤트를 받습니다. 앱이 켜져 있는 동안만 받습니다.
- 앱이 실행될 때, 감지된 Claude Code와 Codex(FR-AGENT-001~003)마다 훅이 설치되어 있는지 확인합니다. 설치되어 있으면 넘어가고, 없거나 낡았으면 설치합니다.
  - 지원 OS는 macOS와 Windows입니다. Windows에서는 Windows에 바로 설치된 에이전트와 WSL 배포판 안의 에이전트 모두에 설치합니다.
  - 두 에이전트가 제공하는 훅 이벤트 전부에 등록합니다.
  - 훅은 앱이 관리하는 셸 스크립트를 부르고, 이 스크립트가 로컬 서버로 이벤트를 POST합니다.
- 훅은 기존 훅과 에이전트를 방해하지 않습니다.
  - 사용자나 다른 도구(Orca, iTerm2 상태 표시 등)가 넣은 훅 항목은 지우거나 고치지 않고, 앱의 항목만 추가합니다.
  - 앱이 꺼져 있거나 서버가 응답하지 않아도 훅은 짧은 시간 안에 조용히 성공으로 끝나며, 에이전트의 동작(도구 실행 허용, 권한 요청 등)을 바꾸는 출력을 내지 않습니다.
- 설치를 막는 권한 문제를 처리합니다. 예: 스크립트 실행 권한, 설정 파일이나 폴더가 없음, 읽기 전용 파일, Codex의 훅 기능 플래그(`[features] hooks`)와 훅 신뢰 승인(`hooks.state`). 처리할 수 없으면 그 에이전트와 환경의 설치 결과를 실패와 이유로 남깁니다.
- 다른 로컬 프로세스가 가짜 이벤트를 보내지 못하게, 훅 요청에는 앱이 만든 토큰을 넣고 서버는 토큰이 맞는 요청만 받습니다.
- 확인용으로 `main` 창에 받은 훅 이벤트를 에이전트, 이벤트 이름과 함께 시간순으로 보여 주는 화면을 추가합니다. Claude Code나 Codex에 질문하면 그 이벤트가 이 화면에 나오는지로 동작을 확인합니다.
- 범위 밖: 이벤트로 캐릭터를 움직이거나 XP를 계산하는 일, 훅 연결 해제는 이번 변경에서 하지 않습니다.

## Capabilities

### New Capabilities

- `hook`: Claude Code와 Codex에 훅을 설치하고, 훅이 보낸 이벤트를 로컬 서버로 받아 renderer에 넘깁니다.

### Modified Capabilities

없음. 설치 대상과 실행 환경은 `agent`의 감지 결과(FR-AGENT-003)를 그대로 받아 씁니다.

## Impact

- `src-tauri`
  - 로직 모듈 `hook/`: 설정 파일 병합과 설치 여부 판정, 이벤트 해석은 `hook/domain/`, 파일 쓰기와 HTTP 서버는 그 밖
  - `tasks/`에 서버를 띄우고 시작 시 설치를 하는 작업, `events.rs`에 훅 이벤트 payload
  - `resources/`에 훅 셸 스크립트
  - `platform/`에 OS별 차이(Windows와 WSL의 경로, 실행 권한)
- `src/renderer`: `api/`에 이벤트 구독, `features/`에 훅 이벤트 목록 화면
- 사용자 PC: `~/.claude/settings.json`, `~/.codex/hooks.json`, `~/.codex/config.toml`과 앱 데이터 폴더의 스크립트를 앱이 고칩니다.
- 의존성: HTTP 서버와 TOML 편집 크레이트가 필요한지는 plan에서 정합니다.
- 설계 문서와 다른 점: `design/mvp-feature-decisions.md`는 "연결하기" 버튼으로 설치한다고 적혀 있지만, 이번 변경은 앱 실행 시 자동으로 설치합니다. clarify에서 확인합니다.
- 참고: Orca(`~/.orca/agent-hooks/`)가 같은 방식(앱 로컬 서버, 엔드포인트 파일에서 포트와 토큰 읽기, 실패해도 `exit 0`, 짧은 curl 타임아웃, Codex 신뢰 해시 등록)을 씁니다. plan에서 그 처리 방식을 확인하고 고른 이유를 적습니다.
