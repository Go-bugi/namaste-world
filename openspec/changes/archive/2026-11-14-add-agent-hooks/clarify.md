### Q1. 앱이 꺼져 있을 때 훅이 보낸 이벤트는 어떻게 하나요?

- 근거: FR-HOOK-001 "나중에 몰아서 반영하지 않는다". Orca는 서버에 보내지 못한 이벤트를 파일(spool)에 쌓아 두었다가 다음 실행 때 읽습니다.
- 선택지: A. 버림(스펙 그대로) / B. Orca처럼 파일에 쌓아 두고 다음 실행 때 반영
- 권장: A. 설계 문서가 "앱이 켜져 있을 때만 XP를 준다"고 정했고, 쌓아 두면 파일 크기 관리와 개인정보(프롬프트 내용) 보관 문제가 생깁니다.

**답**: A. 버립니다. FR-HOOK-001 그대로입니다.

### Q2. Codex 훅 기능 플래그와 신뢰 승인은 어디까지 앱이 처리하나요?

- 근거: FR-HOOK-006 "Codex 훅 기능이 꺼져 있음" 시나리오. Codex는 `config.toml`의 `[features] hooks`가 켜져 있어야 훅을 돌리고, 훅마다 `[hooks.state]`에 신뢰 해시가 있어야 승인 없이 실행합니다. 사용자가 `hooks = false`를 직접 적어 둔 경우가 정해져 있지 않습니다.
- 선택지: A. 플래그가 없을 때만 켜고 신뢰 해시도 기록, 사용자가 `false`로 적어 두었으면 설치를 실패로 남김 / B. `false`여도 켜고 신뢰 해시 기록 / C. 플래그만 켜고 신뢰 승인은 사용자가 Codex에서 직접 함
- 권장: A. 권한 문제는 앱이 풀되(Orca와 같음), 사용자가 일부러 끈 설정은 덮어쓰지 않습니다.

**답**: A. 플래그가 없으면 켜고 신뢰 해시도 기록합니다. 사용자가 `false`로 적어 두었으면 바꾸지 않고 실패로 남깁니다. FR-HOOK-006에 시나리오를 추가했습니다.

### Q3. 쓰기 권한이 없는 설정 파일은 어떻게 하나요?

- 근거: FR-HOOK-006 "쓸 수 없는 설정 파일" 시나리오. 지금은 권한을 바꾸지 않고 실패로 남깁니다.
- 선택지: A. 권한을 바꾸지 않고 실패와 이유를 남김 / B. 사용자 소유 파일이면 쓰기 권한을 더하고 설치한 뒤 원래 권한으로 되돌림
- 권장: A. 사용자나 관리 도구가 일부러 잠근 파일일 수 있어서, 앱이 풀면 그 의도를 깹니다. 화면(FR-HOOK-010)에 이유가 보이므로 사용자가 직접 풀 수 있습니다.

**답**: A. 권한을 바꾸지 않고 실패와 이유를 남깁니다. FR-HOOK-006 그대로입니다.

### Q4. 앱 시작 때 멈춰 있던 WSL 배포판에는 언제 설치하나요?

- 근거: FR-HOOK-002는 "멈춤" 항목에 설치하지 않고, FR-AGENT-007의 다시 감지는 멈춘 배포판을 켜서 확인합니다. 다시 감지 뒤 설치 여부가 정해져 있지 않습니다.
- 선택지: A. 다시 감지로 설치됨이 나온 항목에도 그때 설치 / B. 앱을 다음에 실행할 때까지 설치하지 않음
- 권장: A. 사용자가 다시 감지를 누른 것은 그 에이전트를 쓰겠다는 뜻이고, 앱을 다시 켜야만 설치되면 알기 어렵습니다.

**답**: A. 다시 감지에서 설치됨으로 나온 항목에도 그때 설치합니다. FR-HOOK-002 본문과 시나리오에 반영했습니다.

### Q5. 화면의 훅 이벤트 목록은 몇 개까지 보관하나요?

- 근거: FR-HOOK-010 "이번 실행에서 받은 훅 이벤트". 도구를 많이 쓰면 이벤트가 수천 개 쌓여 메모리와 렌더링이 늘어납니다.
- 선택지: A. 최근 200개 / B. 최근 1000개 / C. 제한 없음
- 권장: A. 동작 확인용 화면이라 최근 이벤트만 보이면 충분합니다.

**답**: A. 최근 200개를 보관합니다. FR-HOOK-010 본문과 시나리오에 반영했습니다.

### Q6. 훅 실행 시간 상한과 화면 표시 지연은 몇 초로 하나요?

- 근거: SC-HOOK-001(훅 2초), SC-HOOK-002(표시 1초). 확인받지 않은 값입니다. 상한이 짧을수록 에이전트가 덜 느려지지만, WSL에서 Windows로 보내는 요청처럼 느린 경로는 실패할 수 있습니다.
- 선택지: A. 훅 2초, 표시 1초 / B. 훅 1초, 표시 0.5초 / C. 훅 5초, 표시 2초
- 권장: A. Orca도 curl 최대 1.5초를 쓰고, WSL 경로는 Orca가 3~5초를 주지만 앱이 꺼져 있을 때마다 에이전트가 5초씩 멈추면 체감됩니다.

**답**: A. 훅 2초, 표시 1초. SC-HOOK-001, SC-HOOK-002 그대로입니다.

### Q7. 받은 훅 이벤트 내용을 디스크에 남기나요?

- 근거: FR-HOOK-009는 훅의 원래 입력(프롬프트, 파일 경로, 도구 출력 포함)을 renderer에 넘기지만, 로그나 파일로 남길지는 정하지 않았습니다.
- 선택지: A. 남기지 않음(메모리에만) / B. 개발 빌드에서만 로그에 남김 / C. 항상 로그 파일에 남김
- 권장: A. 프롬프트와 코드가 들어 있어 디스크에 남기면 개인정보 문제가 생기고, Q1에서 쌓아 두지 않기로 한 결정과도 맞습니다.

**답**: A. 남기지 않습니다. FR-HOOK-012를 추가했습니다.

### Q8. 훅 요청 본문이 아주 크면 어떻게 하나요?

- 근거: FR-HOOK-009 "해석할 수 없는 입력". `PostToolUse`는 도구 출력 전체를 담아 수 MB가 될 수 있는데 크기 상한이 없습니다.
- 선택지: A. 1MB를 넘는 요청은 무시 / B. 1MB를 넘으면 원래 입력 없이 에이전트, 이벤트 이름, 세션 ID만 전달 / C. 크기 제한 없음
- 권장: B. 큰 도구 출력 때문에 이벤트 자체를 잃으면 캐릭터 반응이 빠지므로, 신호는 살리고 무거운 본문만 버립니다.

**답**: 1MB를 넘으면 정해진 필드(에이전트, 이벤트 이름, 받은 시각, 세션 ID, 도구 이름, 도구 호출 ID, 에러 여부, cwd)만 남기고 잘렸다는 표시를 붙입니다. 처음 보기(B)보다 남기는 필드를 늘려 달라는 답에 따라 다시 물어 정했습니다. FR-HOOK-013을 추가했습니다.

### Q9. 앱이 두 개 동시에 실행되면 어느 쪽이 이벤트를 받나요?

- 근거: FR-HOOK-008 "지금 켜진 앱의 서버로". 두 번째로 실행한 앱이 포트와 토큰을 새로 적으면 첫 번째 앱은 이벤트를 받지 못합니다.
- 선택지: A. 앱을 하나만 실행되게 하고, 두 번째 실행은 이미 켜진 앱의 창을 앞으로 가져옴 / B. 마지막에 실행한 앱이 받음 / C. 처음 실행한 앱이 계속 받음
- 권장: A. 데스크톱 펫은 하나만 떠야 자연스럽고, 어느 쪽이 받는지 헷갈릴 일이 없습니다.

**답**: A. 앱은 하나만 실행되고, 두 번째 실행은 켜진 앱의 창을 앞으로 가져옵니다. FR-HOOK-014를 추가했습니다.

### Q10. 훅은 사용자 전역 설정에만 설치하나요?

- 근거: FR-HOOK-002, FR-HOOK-011. 두 에이전트는 프로젝트별 설정(`<프로젝트>/.claude/settings.json`, `<프로젝트>/.codex/`)도 읽습니다. 관리자 정책(Claude Code의 managed settings 등)이 사용자 훅을 막으면 설치해도 동작하지 않습니다.
- 선택지: A. 사용자 전역 설정에만 설치하고, 관리자 정책은 확인하지 않음 / B. 전역 설치에 더해 관리자 정책이 사용자 훅을 막으면 실패로 표시 / C. 프로젝트별 설정에도 설치
- 권장: A. 전역 설정이 모든 프로젝트에 적용되고, 관리자 정책은 회사 PC 같은 드문 경우라 이번 범위에서는 뺍니다.

**답**: A. 사용자 전역 설정에만 설치하고 관리자 정책은 확인하지 않습니다. FR-HOOK-002 본문과 시나리오에 반영했습니다.
