# Clarify

## 질문 (라운드 1)

### Q1. 작은 창이 화면을 벗어났을 때 어느 모니터로 옮기나요?

- 근거: FR-WINDOW-006, FR-WINDOW-010 "주 모니터 작업 영역의 오른쪽 아래 구석". 모니터가 셋 이상이면 원래 자리 옆 모니터가 더 가까울 수 있음
- 선택지: 주 모니터 / 원래 자리에서 가장 가까운 모니터
- 권장: 주 모니터. 어디로 갔는지 늘 같아서 찾기 쉽고, 처음 열 때 모니터를 모를 때 규칙(FR-WINDOW-003)과 같음

**답**: 주 모니터

### Q2. "화면을 벗어났다"를 무엇으로 판정하나요?

- 근거: FR-WINDOW-006, FR-WINDOW-010 "창 중심이 어느 모니터의 작업 영역에도 없으면". 사용자가 일부러 창을 화면 가장자리에 반쯤 걸쳐 둘 수 있음
- 선택지: 창 중심이 어느 작업 영역에도 없을 때 / 창이 작업 영역과 조금도 겹치지 않을 때 / 창 일부라도 작업 영역 밖이면 안쪽으로 밀어 넣기
- 권장: 창 중심 기준. 반쯤 걸쳐 둔 자리는 존중하면서, 끌어서 다시 잡을 수 없는 경우만 옮김

**답**: 창 중심 기준. 창 중심이 어느 모니터의 작업 영역에도 없을 때만 옮김

### Q3. Windows 가상 데스크톱(Win+Tab)에서도 작은 창을 모든 데스크톱에 보이게 하나요?

- 근거: FR-WINDOW-009는 macOS만 다룸. Windows의 항상 위 창은 연 가상 데스크톱에만 보이고, 모든 데스크톱에 고정하는 공개 API가 없음(비공개 COM 인터페이스를 써야 하고 Windows 업데이트마다 깨질 수 있음)
- 선택지: 이번 범위에서 제외 / 포함
- 권장: 제외. 공개 API가 없어 유지 비용이 크고, 필요하면 별도 변경으로 다룸

**답**: 이번 범위에서 제외. Windows에서 작은 창은 연 가상 데스크톱에만 보임

### Q4. 모니터 구성이 바뀐 뒤 몇 초 안에 작은 창을 옮겨야 하나요?

- 근거: FR-WINDOW-010에 시간 제한이 없어 시나리오로 테스트할 수 없음. OS가 모니터를 빼고 배치를 다시 잡는 데 시간이 걸림
- 선택지: 성공 기준 SC-WINDOW-002로 "2초 안" 추가 / 시간 제한 없음
- 권장: 2초 안. OS가 배치를 정리할 시간을 주면서, 사용자가 창이 사라졌다고 느끼기 전에 옮김

**답**: 2초 안. SC-WINDOW-002로 추가

### Q5. Windows에서 다른 앱의 전체 화면 위에도 보여야 하나요?

- 근거: FR-WINDOW-009는 macOS만 다룸. Windows에서 브라우저 F11, 동영상 전체 화면, 창 모드 전체 화면(borderless) 게임 위에는 항상 위 창이 보이지만, 전용 전체 화면(exclusive) 게임 위에는 OS가 막아 보이지 않음
- 선택지: Windows 창 모드 전체 화면 시나리오를 FR-WINDOW-001에 추가하고 전용 전체 화면은 제외한다고 적기 / 스펙에 적지 않음
- 권장: 추가. 지금 설정으로 되는 동작이라 약속으로 남기고, 안 되는 경우도 명시해 둠

**답**: 시나리오 추가. Windows 창 모드 전체 화면 위에 보이고, 전용 전체 화면은 제외한다고 FR-WINDOW-001에 적음
