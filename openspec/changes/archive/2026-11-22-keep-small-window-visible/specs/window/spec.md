## MODIFIED Requirements

### Requirement: FR-WINDOW-001 시작 설정 창에서 작은 창으로 전환

앱은 시작 설정 창의 다음 버튼이 눌리면 작은 창(label `main`)을 열고 시작 설정 창을 닫아야 한다(SHALL). 작은 창은 논리 크기 320×320이고, 제목 표시줄과 테두리가 없고 macOS와 Windows 모두에서 배경이 투명하며, 다른 앱 창보다 항상 위에 뜬다. 다른 앱 창이 포커스를 가져가도, Windows에서 다른 앱이 창 모드 전체 화면이어도 작은 창은 그 창 위에 남는다. Windows의 전용 전체 화면(exclusive fullscreen) 앱 위와, 작은 창을 연 곳이 아닌 Windows 가상 데스크톱에서는 보이지 않아도 된다. Windows 작업 표시줄과 macOS 독에는 앱이 보인다. 작은 창이 열린 뒤에 시작 설정 창을 닫아서, 전환하는 동안 열린 창이 하나도 없는 순간 때문에 앱이 종료되지 않게 한다.

#### Scenario: 다음을 누름

- **WHEN** 시작 설정 창에서 다음을 누름
- **THEN** 작은 창이 열리고 시작 설정 창은 사라지며, 앱은 계속 실행 중이다

#### Scenario: 작은 창 외형

- **WHEN** 작은 창이 열림
- **THEN** 창에는 제목 표시줄과 테두리가 없고, 3D 요소 바깥으로 뒤의 화면이 비쳐 보이며, 다른 앱 창을 눌러도 작은 창이 그 위에 남는다
- **AND** Windows 작업 표시줄과 macOS 독에 앱 아이콘이 보인다

#### Scenario: 다른 앱이 포커스를 가져감

- **WHEN** 작은 창이 열린 상태에서 다른 앱을 실행하거나, Cmd+Tab 또는 Alt+Tab으로 다른 앱으로 전환하거나, 다른 앱 창을 작은 창과 겹치게 옮김
- **THEN** 작은 창은 그 앱 창 위에 그대로 보인다

#### Scenario: Windows에서 다른 앱의 전체 화면

- **WHEN** Windows에서 작은 창이 열린 상태로 브라우저를 F11로 전체 화면으로 바꾸거나 동영상을 전체 화면으로 재생함
- **THEN** 작은 창이 그 전체 화면 위에 보인다

#### Scenario: 다음을 두 번 빠르게 누름

- **WHEN** 다음 버튼을 연달아 두 번 누름
- **THEN** 작은 창은 하나만 열린다

### Requirement: FR-WINDOW-006 열려 있는 창 다시 보이기

앱은 사용자가 앱을 다시 불러낼 때(macOS 독 아이콘 클릭, 앱 다시 실행) 그 시점에 쓰는 창을 보여 주어야 한다(SHALL). 작은 창으로 넘어간 뒤면 작은 창을, 그 전이면 시작 설정 창을 보여 준다. 작은 창을 보여 줄 때 창 중심이 어느 모니터의 작업 영역에도 없으면, 주 모니터 작업 영역의 오른쪽 아래 구석(FR-WINDOW-003, FR-WINDOW-005와 같은 여백과 크기)으로 옮긴 뒤 보여 준다. 창 중심이 작업 영역 안에 있으면 자리를 옮기지 않는다.

#### Scenario: 작은 창을 닫은 뒤 독 아이콘 클릭

- **WHEN** macOS에서 작은 창으로 넘어간 뒤 작은 창을 닫고 독 아이콘을 누름
- **THEN** 작은 창이 다시 보이고 시작 설정 창은 열리지 않는다

#### Scenario: 숨긴 동안 모니터를 뺌

- **WHEN** 작은 창을 보조 모니터에 둔 채 닫고, 보조 모니터를 뺀 뒤 독 아이콘을 누르거나 앱을 다시 실행함
- **THEN** 작은 창이 주 모니터 작업 영역의 오른쪽 아래 구석에 보인다

#### Scenario: 보이는 자리에 있던 창

- **WHEN** 작은 창을 화면 왼쪽 위로 끌어 옮긴 뒤 닫고 독 아이콘을 누름
- **THEN** 작은 창은 옮겨 둔 왼쪽 위 자리에 다시 보인다

## ADDED Requirements

### Requirement: FR-WINDOW-009 macOS 모든 데스크톱과 전체 화면 위에 표시

macOS에서 작은 창은 사용자가 어느 데스크톱(Spaces)에 있든, 다른 앱이 전체 화면이든 다른 앱 창 위에 보여야 한다(SHALL). 작은 창은 일반 항상 위(floating) 레벨에 두어 메뉴 막대, 알림, 시스템 대화 상자는 가리지 않는다. 데스크톱을 옮겨도 작은 창의 화면 위치는 그대로다.

#### Scenario: 데스크톱 전환

- **WHEN** macOS에서 작은 창이 열린 상태로 Ctrl+→ 또는 세 손가락 스와이프로 옆 데스크톱으로 옮김
- **THEN** 작은 창이 옮긴 데스크톱에서도 같은 화면 위치에 보인다

#### Scenario: 다른 앱의 전체 화면

- **WHEN** macOS에서 작은 창이 열린 상태로 다른 앱 창을 전체 화면으로 바꿈
- **THEN** 작은 창이 그 전체 화면 앱 위에 보인다

#### Scenario: 시스템 UI는 가리지 않음

- **WHEN** macOS에서 작은 창이 화면 위쪽에 있고 메뉴 막대 메뉴를 열거나 알림이 뜸
- **THEN** 메뉴와 알림이 작은 창보다 위에 보인다

### Requirement: FR-WINDOW-010 모니터 구성이 바뀌면 보이는 곳으로 옮기기

앱은 작은 창이 열려 보이는 동안 모니터가 빠지거나 추가되거나, 해상도, 배율, 배치가 바뀌면 작은 창의 위치를 다시 확인해야 한다(SHALL). 창 중심이 어느 모니터의 작업 영역에도 없으면 주 모니터 작업 영역의 오른쪽 아래 구석(FR-WINDOW-003, FR-WINDOW-005와 같은 여백과 크기)으로 옮긴다. 창 중심이 작업 영역 안에 있으면 옮기지 않는다. 바뀐 뒤에도 창은 FR-WINDOW-004대로 같은 논리 크기로 보인다.

#### Scenario: 작은 창이 있던 모니터를 뺌

- **WHEN** 작은 창이 보조 모니터에 있는 상태에서 보조 모니터 케이블을 뺌
- **THEN** 작은 창이 주 모니터 작업 영역의 오른쪽 아래 구석으로 옮겨져 보인다

#### Scenario: 다른 모니터를 뺌

- **WHEN** 작은 창이 주 모니터에 있는 상태에서 보조 모니터를 뺌
- **THEN** 작은 창은 주 모니터의 원래 자리에 그대로 있다

#### Scenario: 해상도를 낮춤

- **WHEN** 작은 창이 오른쪽 아래 구석에 있는 상태에서 그 모니터의 해상도를 낮춰 창 중심이 작업 영역 밖으로 나감
- **THEN** 작은 창이 주 모니터 작업 영역의 오른쪽 아래 구석으로 옮겨져 보인다

#### Scenario: 모니터 배치를 바꿈

- **WHEN** 디스플레이 설정에서 보조 모니터의 배치를 바꿔 작은 창의 중심이 어느 모니터에도 없게 됨
- **THEN** 작은 창이 주 모니터 작업 영역의 오른쪽 아래 구석으로 옮겨져 보인다

### Requirement: SC-WINDOW-002 모니터 구성 변경 뒤 옮기는 시간

모니터 구성이 바뀌어 FR-WINDOW-010대로 작은 창을 옮겨야 할 때, 앱은 OS가 구성 변경을 알린 뒤 2초 안에 작은 창을 옮긴 자리에 보여야 한다(MUST).

#### Scenario: 모니터를 뺀 뒤

- **WHEN** 작은 창이 보조 모니터에 있는 상태에서 보조 모니터를 뺌
- **THEN** 2초 안에 작은 창이 주 모니터 작업 영역의 오른쪽 아래 구석에 보인다
