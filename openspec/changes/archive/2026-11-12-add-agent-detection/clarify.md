# Clarify

## 질문 (라운드 1)

충돌 검사: `conflicts`가 비어 있고 `openspec/specs/`에 기준 스펙이 없어서 충돌은 없습니다. 아래는 모호한 점입니다.

### Q1. 어느 WSL 배포판을 확인하고, 꺼져 있는 배포판은 켜서 확인하나요?

- 근거: FR-AGENT-002 "설치된 WSL 배포판 각각", FR-AGENT-005. 꺼진 배포판 안에서 명령을 실행하면 WSL이 배포판을 켜므로 몇 초가 걸리고 메모리를 씁니다. `docker-desktop` 같은 도구용 배포판도 목록에 나옵니다.
- 선택지: A. 모든 배포판을 확인하고 꺼진 것은 켬(도구용 배포판 제외) / B. 실행 중인 배포판만 확인하고 꺼진 것은 "확인 안 함"으로 냄 / C. 기본 배포판 하나만 확인
- 권장: A. 나중에 로그인과 질문을 하려면 어차피 배포판을 켜야 하고, 꺼져 있다는 이유로 설치된 에이전트를 놓치면 안 됩니다.

**답**: A. 모든 배포판을 확인하고 꺼진(Stopped) 배포판도 켜서 확인합니다. 도구용 배포판(`docker-desktop` 등)은 제외합니다. FR-AGENT-002에 반영했습니다.

### Q2. 감지 시간 상한은 몇 초인가요?

- 근거: SC-AGENT-001. WSL 배포판을 처음 켜면 몇 초가 걸릴 수 있습니다.
- 선택지: A. 10초 / B. 5초 / C. 20초
- 권장: A. 꺼진 WSL을 켜는 시간을 감당하면서도 사용자가 기다릴 만한 범위입니다.

**답**: A. 10초. SC-AGENT-001 그대로입니다.

### Q3. 실행 파일은 찾았는데 버전을 읽지 못하면 어떻게 내나요?

- 근거: FR-AGENT-003 "버전을 읽지 못함" 시나리오. 지금은 "설치됨 + 버전 알 수 없음"으로 적어 두었습니다.
- 선택지: A. 설치됨, 버전 알 수 없음 / B. 확인 실패(이유: 버전 확인 실패)
- 권장: B. `--version`에도 응답하지 않는 실행 파일은 로그인이나 질문에도 쓸 수 없을 가능성이 높아서, 이후 기능이 쓸 수 있다고 오해하지 않게 합니다.

**답**: B. 확인 실패로 냅니다. FR-AGENT-003 시나리오를 고쳤습니다.

### Q4. 감지 결과를 보여 주는 화면까지 이번 범위에 넣나요?

- 근거: proposal "범위 밖" 항목. 스펙에는 화면 요구사항이 없습니다.
- 선택지: A. Rust 명령과 `api/` 함수까지만(화면 없음) / B. 결과를 목록으로 보여 주는 간단한 화면까지 / C. "연결하기" 흐름에 맞춘 정식 화면까지
- 권장: A. 화면은 훅 설치("연결하기")와 함께 설계하는 편이 맞고, 이번에는 이후 기능이 쓸 감지 결과만 확정합니다.

**답**: B. 결과를 목록으로 보여 주는 간단한 화면까지 넣습니다. FR-AGENT-008을 추가하고 proposal의 범위를 고쳤습니다.

### Q5. 언제 감지하고, 결과를 저장해 두나요?

- 근거: FR-AGENT-001 "renderer가 요청하면". 같은 결과를 여러 번 요청할 때의 동작이 정해지지 않았습니다.
- 선택지: A. 요청할 때마다 새로 감지하고 저장하지 않음 / B. 앱 시작 때 한 번 감지해 두고, 요청하면 저장한 결과를 줌(다시 감지 요청은 따로) / C. 결과를 디스크에 저장해 다음 실행에도 씀
- 권장: A. 설치 상태는 앱이 모르게 바뀔 수 있고, 감지 요청이 자주 오지 않아서 저장할 이유가 적습니다.

**답**: B. 앱 시작 때 한 번 감지해 두고 요청하면 저장한 결과를 주며, 다시 감지는 따로 요청합니다. 디스크에는 저장하지 않습니다. FR-AGENT-001을 고치고 FR-AGENT-007을 추가했습니다.

## 질문 (라운드 2)

라운드 1 답으로 새로 생긴 FR-AGENT-007(결과 보관과 다시 감지)과 FR-AGENT-008(목록 화면)에서 정해지지 않은 점만 묻습니다. `conflicts`는 여전히 비어 있습니다.

### Q6. 목록 화면은 어디에 두나요?

- 근거: FR-AGENT-008. 지금 앱은 `main` 창 하나이고, 그 창은 3D 데모와 템플릿 링크를 보여 줍니다.
- 선택지: A. `main` 창에 목록을 한 영역으로 추가 / B. 새 창(`agents`)을 만들고 트레이나 메뉴로 엶 / C. 개발 모드에서만 `main` 창에 보임
- 권장: A. 정식 화면은 "연결하기"와 함께 다시 설계하므로, 지금은 창을 늘리지 않고 확인용으로 붙입니다.

**답**: A. `main` 창에 목록을 한 영역으로 추가합니다. FR-AGENT-008에 반영했습니다.

### Q7. 감지가 진행 중일 때 다시 감지를 또 요청하면 어떻게 하나요?

- 근거: FR-AGENT-007 "다시 감지", FR-AGENT-008 "다시 감지 버튼". 꺼진 WSL을 켜면 감지가 몇 초 걸려 버튼을 여러 번 누를 수 있습니다.
- 선택지: A. 새로 시작하지 않고 진행 중인 감지의 결과를 함께 받음(화면 버튼은 진행 중에 비활성) / B. 진행 중인 감지를 버리고 새로 시작 / C. 요청을 거절하고 "이미 감지 중" 에러를 돌려줌
- 권장: A. 감지를 겹쳐 돌리면 WSL 명령이 쌓여 10초 상한을 넘기기 쉽고, 결과는 어차피 같습니다.

**답**: 다시 감지는 화면의 버튼으로 하고, 감지가 진행 중이면(앱 시작 감지 포함) 버튼을 비활성화했다가 끝나면 다시 활성화합니다. FR-AGENT-008에 반영했습니다. 버튼 밖에서 명령으로 겹쳐 요청하는 경우는 정하지 않았습니다.

### Q8. 다시 감지하는 동안 결과를 요청하면 무엇을 주고, 화면은 어떻게 보이나요?

- 근거: FR-AGENT-007 "보관한 결과 요청"은 감지가 끝난 뒤만 정했고, FR-AGENT-008 "감지 중"은 처음 감지만 생각했습니다.
- 선택지: A. 이전 결과를 바로 주고, 화면은 이전 결과를 둔 채 확인 중 표시만 더함 / B. 새 감지가 끝날 때까지 기다렸다가 새 결과를 주고, 화면은 이전 결과를 지우고 확인 중만 보임
- 권장: A. 다시 감지하는 몇 초 동안 목록이 사라지지 않고, 이후 기능(로그인 등)도 그동안 이전 결과를 쓸 수 있습니다.

**답**: A. 다시 감지하는 동안 결과를 요청하면 이전 결과를 바로 주고, 화면은 이전 결과를 둔 채 확인 중 표시를 더합니다. FR-AGENT-007, FR-AGENT-008에 반영했습니다.

### Q9. 버튼 밖에서 다시 감지 명령이 겹쳐 오면 어떻게 하나요?

- 근거: FR-AGENT-007 "다시 감지". 화면 버튼은 감지 중에 비활성화되지만, 앱 시작 감지 중에 명령이 오거나 다른 창이나 이후 기능(연결하기, 로그인)이 명령을 직접 부르면 감지가 겹칠 수 있습니다.
- 선택지: A. 새로 시작하지 않고 진행 중인 감지의 결과를 함께 받음 / B. 진행 중인 감지를 버리고 새로 시작 / C. "이미 감지 중" 에러를 돌려줌
- 권장: A. 감지를 겹쳐 돌리면 WSL 명령이 쌓여 10초 상한을 넘기기 쉽고, 부르는 쪽은 에러 처리 없이 최신 결과를 받습니다.

**답**: 이번 변경에서는 정하지 않습니다. 명령을 직접 부르는 기능(연결하기, 로그인)을 만들 때 그 변경의 clarify에서 정합니다. delta는 바꾸지 않았습니다.

## 질문 (라운드 4)

라운드 1 Q1의 답을 Orca의 방식과 비교해 다시 묻습니다. Orca(`stablyai/orca`의 `src/main/wsl/discovery/wsl-background-exec-gate.ts`)는 백그라운드 작업에서 멈춘 배포판을 켜지 않고, 사용자가 직접 한 동작일 때만 켭니다. `conflicts`는 여전히 비어 있습니다.

### Q10. 멈춘(Stopped) WSL 배포판은 언제 켜서 확인하나요?

- 근거: FR-AGENT-002 "멈춘 배포판" 시나리오, FR-AGENT-007 앱 시작 감지. 지금 스펙대로면 앱을 켤 때마다 멈춘 배포판이 모두 켜져 몇 초씩 걸리고 메모리를 수백 MB 씁니다.
- 선택지: A. 앱 시작 감지는 실행 중인 배포판만 확인하고 멈춘 배포판은 "멈춤"으로 냄. 다시 감지 버튼을 누르면 멈춘 배포판도 켜서 확인(Orca 방식) / B. 지금처럼 앱 시작 감지에서도 모두 켜서 확인 / C. 멈춘 배포판은 언제나 켜지 않고 "멈춤"으로만 냄
- 권장: A. 사용자가 요청하지 않았는데 WSL을 켜지 않고, 버튼을 누르면 빠짐없이 감지합니다.

**답**: A. 앱 시작 감지는 실행 중인 배포판만 확인하고 멈춘 배포판은 "멈춤"으로 냅니다. 다시 감지 버튼을 누르면 멈춘 배포판도 켜서 확인합니다. 라운드 1 Q1의 답을 이것으로 바꿉니다. FR-AGENT-002, FR-AGENT-008에 반영했습니다.
