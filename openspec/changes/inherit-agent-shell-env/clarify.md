## 질문 (라운드 1)

### Q1. Windows 셸 선택 단계를 어디에 둘까요?

- 근거: FR-START-002, FR-START-013. 앱 시작 감지(FR-AGENT-007)는 창이 열리기 전에 이미 시작합니다. 셸 선택이 감지 결과를 바꾸므로 단계 위치와 다시 감지 시점이 함께 정해집니다.
- 선택지: 감지 앞 맨 첫 단계, 셸을 바꾸면 바로 다시 감지 / 감지 단계 안에 셸 선택을 함께 두기(단계 수 그대로) / 로그인 확인 단계 앞에 두기
- 권장: 감지 앞 맨 첫 단계. 감지, 훅 설치, 모델 목록이 모두 셸 환경에 기대므로 가장 먼저 정하는 것이 흐름에 맞습니다(Orca도 온보딩 앞부분에서 묻습니다).

**답**: 감지 앞 맨 첫 단계, 셸을 바꾸면 바로 다시 감지

### Q2. PowerShell 선택지는 어떤 PowerShell을 쓸까요?

- 근거: FR-AGENT-014. PowerShell 7(`pwsh`)과 Windows PowerShell 5.1은 프로필 파일이 서로 다릅니다.
- 선택지: PowerShell 7이 있으면 7, 없으면 5.1 / 선택지를 PowerShell 7과 Windows PowerShell 둘로 나누기 / 항상 Windows PowerShell 5.1
- 권장: 7이 있으면 7, 없으면 5.1. Orca와 같고, 선택지가 늘지 않습니다.

**답**: PowerShell 7이 있으면 7, 없으면 Windows PowerShell 5.1

### Q3. 셸 환경 읽기의 시간 상한을 몇 초로 할까요?

- 근거: SC-AGENT-003. 지금 macOS `PATH` 읽기는 3초입니다. 감지 전체 상한은 10초(SC-AGENT-001)입니다. nvm 같은 도구를 쓰는 셸 설정이나 PowerShell 프로필은 1~3초 넘게 걸리기도 합니다.
- 선택지: 5초 / 3초(지금과 같음) / 8초
- 권장: 5초. 느린 셸 설정도 대부분 담고, 남은 5초로 감지를 마칠 수 있습니다.

**답**: 5초

### Q4. 셸에서 읽은 API 키를 CLI에 넘기는 것이 FR-AGENT-011과 충돌하지 않게 어떻게 할까요?

- 근거: FR-AGENT-011은 "토큰을 직접 읽지 않아야 한다"고 적었습니다. FR-AGENT-012~014는 셸 환경 전체를 읽어 넘기므로 `ANTHROPIC_API_KEY` 같은 값이 앱 프로세스 메모리를 거칩니다.
- 선택지: FR-AGENT-011을 MODIFIED로 고쳐 "셸 환경을 CLI에 넘기는 것은 허용, 값을 해석하거나 따로 쓰지 않음"을 적기 / FR-AGENT-011은 그대로 두고 FR-AGENT-017만으로 충분하다고 보기 / 인증 관련 변수는 셸 환경에서 빼고 넘기기
- 권장: FR-AGENT-011을 고치기. 두 요구사항이 말 그대로 부딪히므로 기준 스펙에서 뜻을 분명히 해야 테스트를 쓸 수 있습니다. 인증 변수를 빼면 이슈가 해결되지 않습니다.

**답**: FR-AGENT-011을 MODIFIED로 고침. 셸 환경은 에이전트 CLI 프로세스에 그대로 넘기는 데만 쓰고, 값을 해석하거나 CLI 실행이 아닌 요청과 처리에 쓰지 않음. 보안상 위험은 값을 얻는 것이 아니라 새는 경로(디스크, renderer, CLI 밖 사용)이므로 FR-AGENT-017과 함께 막음

### Q5. 셸 환경을 읽지 못했을 때 화면에 알릴까요?

- 근거: FR-AGENT-016은 받은 환경으로 조용히 진행합니다. 이 이슈의 불만이 "왜 터미널과 다른지 알 수 없다"는 것이라, 조용히 넘어가면 같은 문제가 남습니다.
- 선택지: 감지 단계에 "셸 설정을 읽지 못해 셸 설정 파일의 환경 변수가 반영되지 않았습니다"와 이유(시간 초과, 오류 종료 등)를 보여 주기 / 알리지 않기
- 권장: 감지 단계에 보여 주기. 이유에는 환경 변수 값은 담지 않습니다(FR-AGENT-017).

**답**: 감지 단계에 셸 설정 파일의 환경 변수가 반영되지 않았다는 안내와 이유를 보여 줌(FR-AGENT-018). 이유에 환경 변수 값은 담지 않음

### Q6. 앱 시작 감지가 진행 중일 때 셸을 바꾸면 어떻게 할까요?

- 근거: FR-START-013, FR-START-005. 셸 선택 단계의 다음 버튼은 항상 활성화되고, 창이 열릴 때 앱 시작 감지는 이미 진행 중입니다. 셸을 바꾸면 다시 감지가 시작되는데, 진행 중인 감지와 겹칠 때의 동작이 정해져 있지 않습니다. FR-AGENT-008은 감지 중에 다시 감지 버튼을 비활성화합니다.
- 선택지: 진행 중인 감지가 끝난 뒤 새 셸로 다시 감지(마지막 선택만 반영) / 진행 중인 감지를 버리고 바로 새 셸로 감지 / 감지 중에는 셸 선택지를 비활성화
- 권장: 끝난 뒤 다시 감지. 지금 감지 구조를 그대로 쓰고, 여러 번 바꿔도 마지막 선택으로 한 번만 다시 감지합니다.

**답**: Windows에서는 앱을 켤 때 감지하지 않고, 셸 선택 단계에서 다음을 누를 때 고른 셸로 감지를 시작함. 돌아와서 다른 셸로 다음을 누르면 다시 감지, 같은 셸이면 하지 않음. FR-AGENT-007을 MODIFIED로 고치고 FR-START-012, FR-START-013을 고침
### Q7. 설정 폴더가 바뀌면 이전 폴더에 설치한 앱 훅은 어떻게 할까요?

- 근거: FR-HOOK-002. 셸을 바꾸거나 셸 설정 파일의 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`을 바꾸면 훅을 새 폴더에 설치합니다. 이전 폴더에 설치한 앱 훅을 어떻게 할지는 정해져 있지 않습니다.
- 선택지: 이전 폴더는 그대로 둠 / 이번 실행에서 앱이 설치한 이전 폴더의 앱 훅만 지움
- 권장: 그대로 둠. 훅 스크립트는 앱 폴더(`~/.namaste-world`)에 있어서 이전 폴더의 훅도 정상 동작하고 다른 도구의 훅을 건드릴 위험이 없습니다. 사용자가 이전 폴더로 CLI를 써도 이벤트가 옵니다.

**답**: 이전 폴더의 앱 훅은 그대로 둠. FR-HOOK-002에 문장과 시나리오 추가

### Q8. 셸을 바꿔 다시 감지할 때 멈춘 WSL 배포판을 켤까요?

- 근거: FR-START-013은 셸을 바꾸고 다음을 누르면 FR-AGENT-007의 다시 감지를 실행합니다. FR-AGENT-002는 다시 감지 때 멈춘(Stopped) 배포판을 켜서 확인합니다. 하지만 셸 선택은 Windows 환경에만 영향을 주고 WSL과는 상관없어서, 셸만 바꿨는데 배포판이 켜집니다.
- 선택지: 다시 감지 전체를 하되 앱 시작 감지처럼 멈춘 배포판은 켜지 않음 / Windows 환경만 다시 확인하고 WSL 결과는 그대로 둠 / 다시 감지 버튼과 같이 멈춘 배포판도 켬
- 권장: 멈춘 배포판은 켜지 않음. 셸 선택과 상관없는 부작용을 막고, 감지 흐름은 하나로 유지합니다. 배포판을 켜려면 감지 단계의 다시 감지 버튼을 쓰면 됩니다.

**답**: 켜지 않음. 셸을 바꿔 하는 다시 감지는 앱 시작 감지처럼 멈춘 WSL 배포판을 켜지 않음. 켜려면 감지 단계의 다시 감지 버튼을 씀. FR-START-013에 문장과 시나리오 추가
