# 작업 상태 표시와 3D 모델링

PRD(`design/prd.md`)의 M1 중 작업 상태 표시(3.1), 앱 비주얼(3.3), 레벨별 방 모습(3.4)을 만들기 위해 정할 것과 할 일을 적습니다. 정한 내용은 기능 스펙(`openspec/`)으로 옮기고, 이 문서에는 결정과 근거만 남깁니다.

우선순위 기준은 PRD와 같습니다.

- **P0**: 정하지 않으면 그 기능의 스펙을 쓸 수 없습니다.
- **P1**: 스펙은 쓸 수 있지만 구현 중에 막힙니다.
- **P2**: 기본값으로 먼저 만들고 나중에 바꿔도 됩니다.

## 1. 작업 상태 표시

### 1.1 상태

| 상태      | 언제                                            | 캐릭터                          |
| --------- | ----------------------------------------------- | ------------------------------- |
| 대기      | 진행 중인 질문이 없을 때                        | 의자에 앉아 졸고 있음           |
| 깨어남    | 대기 중에 마우스를 캐릭터 위에 올렸을 때        | 눈을 뜨고 커서 쪽을 봄          |
| 작업 중   | 질문을 보낸 뒤 에이전트가 답을 마칠 때까지      | 노트북으로 일함                 |
| 에러      | 에이전트의 도구 실행이 실패했을 때              | 당황함                          |
| 거부      | 사용자가 도구 실행을 거부했거나 훅이 막았을 때  | "Sorry sir" 같은 반응           |
| 확인 필요 | 에이전트가 사용자에게 권한이나 확인을 기다릴 때 | 손을 들거나 화면 쪽을 보며 부름 |

### 1.2 지금 받을 수 있는 신호

앱은 이미 두 에이전트의 훅 이벤트를 받아 renderer로 넘기고 있습니다(`src-tauri/src/hook/domain/`).

- **Claude Code**: 31개 이벤트를 등록합니다. 상태 표시에 쓸 만한 것은 `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `Notification`, `Elicitation`, `Stop`, `StopFailure`, `SessionEnd`입니다.
- **Codex**: 0.146.0에서 확인한 11개 이벤트를 등록합니다. `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `Stop`, `SessionEnd` 등입니다. 0.169.0부터는 `Interrupt`, `PreModelRequest`, `PostModelRequest`가 더해집니다. 도구 실패만 따로 알리는 이벤트는 없습니다.
- **renderer가 받는 값**: 에이전트, 이벤트 이름, 받은 시각, 세션 ID, 도구 이름, 도구 호출 ID, 에러 여부, 작업 폴더, 원래 본문입니다. 본문이 너무 크면 원래 본문은 빠집니다.
- **에러 여부**: 이벤트가 `PostToolUseFailure`면 에러입니다. 그 밖에는 `tool_response.is_error`를 쓰고, 없으면 `tool_response.success`의 반대 값을 씁니다. 둘 다 없으면 알 수 없음입니다.

상태와 신호를 이어 본 후보입니다. 실제 이벤트로 확인하기 전까지는 후보입니다.

| 상태      | Claude Code 후보                                   | Codex 후보                          | 확인할 것                                                                                  |
| --------- | -------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------ |
| 작업 중   | `UserPromptSubmit`부터 `Stop`, `StopFailure`까지   | `UserPromptSubmit`부터 `Stop`까지   | 답 중간에 사용자가 멈췄을 때 `Stop`이 오는지. Codex는 `Interrupt`가 오는지                 |
| 확인 필요 | `PermissionRequest`, `Notification`, `Elicitation` | `PermissionRequest`                 | 승인하거나 거부한 뒤 어떤 이벤트로 풀리는지. `Notification`에서 권한 알림만 가를 수 있는지 |
| 에러      | `PostToolUseFailure`                               | `PostToolUse`의 에러 여부           | Codex `tool_response`에 실패가 실제로 표시되는지                                           |
| 거부      | `PermissionDenied`                                 | 아직 없음                           | `PermissionDenied`가 사용자 거부인지 자동 판정 거부인지. 훅 차단은 어떤 이벤트로 오는지    |
| 대기      | 진행 중인 질문이 없음, `SessionEnd`                | 진행 중인 질문이 없음, `SessionEnd` | 터미널을 그냥 닫았을 때 `SessionEnd`가 오는지                                              |

| S-06 | 서브에이전트              | `SubagentStart`부터 `SubagentStop`까지도 그 세션의 작업 중으로 봅니다. 서브에이전트 안의 확인 필요와 에러도 같은 규칙을 따릅니다. 서브에이전트를 따로 보여 주는 연출은 M2 후보입니다.                                                                                  |
| S-07 | 앱을 켤 때 진행 중인 질문 | 시작 신호를 놓친 세션이라도 이벤트가 하나라도 오면 작업 중으로 보고, `Stop`이나 5분 무신호(S-03)로 끝냅니다. 시작 신호를 받지 못한 그 질문은 경험치에 세지 않습니다.                                                                                                   |

### 2.3 기술 제약

- **작은 창 크기**: 논리 크기 320×320이고, 배경이 투명하며 항상 다른 창 위에 뜹니다(FR-WINDOW-001). 이 크기에서도 상태가 실루엣과 동작만으로 구분되어야 합니다.
- **에셋은 앱 안에서만 불러옵니다**: CSP가 외부 주소를 막습니다. 모델은 `src/renderer/public/models/`에 둡니다. meshopt 디코더는 three.js에 JS로 들어 있어 따로 넣을 파일이 없습니다(M-03). 환경맵은 drei `Environment`의 `preset` 대신 앱 안의 HDR 파일을 씁니다.
- **계속 켜져 있는 앱입니다**: 하루 종일 렌더링하므로 대기 중에는 프레임을 낮추는 등 CPU와 GPU 사용을 줄여야 합니다.
- **지금 씬**: 시험용 3D 요소 하나만 있습니다(`src/renderer/src/scene/TestScene.tsx`).

## 3. 진행 순서

상태 판정과 3D는 따로 만들 수 있어서 둘을 나눠 진행합니다.

1. **실제 이벤트 모으기**: Claude Code와 Codex에서 질문, 승인, 거부, 도구 에러, 중간에 멈추기를 직접 해 보고 받은 이벤트를 기록합니다. 그 결과로 S-01을 확정합니다.
2. **상태 판정 만들기**: S-01~S-07에 따라 이벤트에서 상태를 계산하는 부분을 스펙으로 씁니다. 처음에는 3D 대신 글자나 색으로 상태를 보여 줘도 됩니다.
3. **회색 모델로 구도 잡기**: M-01~M-04에 따라 색과 디테일 없는 간단한 모델로 320×320 창에서 구도와 크기를 확인합니다.
4. **캐릭터 애니메이션 붙이기**: 2.2의 동작을 만들고 2단계의 상태에 연결합니다.
5. **레벨별 오브젝트 만들기**: 2.5대로 의자, 책상, 창문의 5단계를 만듭니다.
