# Namaste World PRD

마일스톤별로 만들 것과 그 안에서 정할 것을 적은 기획 기준 문서입니다. 구현하면서 정한 세부 동작은 기능별 스펙(`openspec/specs/`)에 있고, 이 문서에는 범위와 결정만 적습니다.

## 1. 개요

### 제품

PC 한쪽에 떠 있는 작은 3D 방에서 인도 개발자 캐릭터가 사용자의 AI 에이전트 작업에 맞춰 움직입니다. 사용자가 Claude Code나 Codex에 질문하면 캐릭터가 일하고, 확인이 필요하면 손을 들고, 하루를 마치면 그날 한 일을 유튜버처럼 정리해 보여 줍니다.

### 대상 사용자

터미널이나 IDE에서 Claude Code, Codex를 매일 쓰는 개발자입니다. 앱은 에이전트를 대신 쓰지 않고, 사용자가 원래 쓰던 에이전트를 옆에서 지켜봅니다.

### 톤

인도 개발자 문화를 애정 있게 비트는 패러디입니다. 힝글리시, "Kindly do the needful", 주가드, 방갈로르, 튜토리얼 유튜브 말투를 씁니다. 실명과 실제 브랜드는 쓰지 않습니다.

### 바꾸지 않는 원칙

- 캐릭터는 한 명입니다. 수집, 가챠, 여러 캐릭터는 넣지 않습니다.
- 확실한 신호만 셉니다. 작업 내용을 보고 유형(버그 수정, 기능 개발 등)을 판정해 점수를 주지 않습니다.
- 사용자 PC에 설치된 CLI만 씁니다. 앱이 Anthropic이나 OpenAI API를 직접 부르지 않고, 로그인 정보도 다루지 않습니다.

## 3. M1 요구사항

### 3.1 작업 상태 표시

사용자가 AI 에이전트에 질문하고 답을 받는 흐름을 캐릭터의 상태로 보여 줍니다.

| 상태      | 언제                                            | 캐릭터                                |
| --------- | ----------------------------------------------- | ------------------------------------- |
| 대기      | 진행 중인 질문이 없을 때                        | 의자에 앉아 졸고 있음(동작은 정할 것) |
| 깨어남    | 대기 중에 마우스를 캐릭터 위에 올렸을 때        | 눈을 뜨고 커서 쪽을 봄                |
| 작업 중   | 질문을 보낸 뒤 에이전트가 답을 마칠 때까지      | 노트북으로 일함                       |
| 에러      | 에이전트의 도구 실행이 실패했을 때              | 당황함                                |
| 거부      | 사용자가 도구 실행을 거부했거나 훅이 막았을 때  | "Sorry sir" 같은 반응                 |
| 확인 필요 | 에이전트가 사용자에게 권한이나 확인을 기다릴 때 | 손을 들거나 화면 쪽을 보며 부름       |

- "질문"은 사용자가 에이전트에 보낸 프롬프트 한 번입니다. 앱이 질문을 보내는 것이 아니라, 사용자가 터미널이나 IDE에서 보낸 질문을 훅으로 알아챕니다.
- 에러와 거부는 다르게 반응합니다. Claude Code 로그 조사에서 도구 에러의 약 30%가 훅 차단이나 사용자 거부였기 때문입니다.
- 상태를 판정하는 신호, 상태끼리의 우선순위, 상태별 동작은 `design/state-and-modeling.md`에서 정합니다.

### 3.2 퇴근과 하루 정리 영상

사용자가 퇴근 버튼을 누르면 직전 퇴근부터 지금까지 한 질문을 정리한 짧은 영상을 보여 줍니다.

- **화면**: 3D 방 위에 작은 창이 뜨고, 캐릭터가 인도 테크 유튜버처럼 그날 작업을 소개합니다("Hello friends, today we will learn..."). 내용은 자막으로 보여 줍니다.
- **소리**: 알아들을 수 없는 음절을 자막 글자에 맞춰 웅얼거립니다(동물의 숲의 대사 소리 같은 방식). 실제 음성 합성은 쓰지 않습니다.
- **구성**: 그 기간의 작업에서 중요한 주제를 최대 3개 뽑고, 영상을 주제별 섹션으로 나눠 보여 줍니다.
- **기간**: 직전 퇴근 시각부터 이번 퇴근 시각까지입니다. 퇴근한 적이 없을 때와 며칠 퇴근하지 않았을 때는 5장 D-07에서 정합니다.
- 파일로 내보내기는 M1에 넣지 않습니다.

### 3.3 앱 비주얼

- **형태**: 배경 없는 작은 창에 3D 방이 PC 화면 한쪽에 계속 떠 있습니다.
- **구성**: 인도 개발자, 의자, 책상(노트북 포함), 창문 네 가지로 방을 만듭니다. 그림은 three.js 로우 폴리 3D이고 에셋은 직접 만듭니다.
- 에셋 목록, 모델링과 애니메이션 방식은 `design/state-and-modeling.md`에서 정합니다.

### 3.4 레벨

- **질문할수록 경험치가 쌓이고 레벨이 오릅니다.** 질문 수 말고 다른 신호(도구 사용, 고친 파일)를 경험치에 넣을지는 5장 D-01에서 정합니다.
- **M1은 Lv1~Lv5입니다.** 숫자로만 표시하고, 연봉 같은 돈 표현은 쓰지 않습니다.
- **레벨이 오르면 의자, 책상, 창문의 품질이 한 단계씩 좋아집니다.** 세 물건마다 5단계 모델이 필요합니다. 단계별 모습은 `design/state-and-modeling.md`에서 정합니다.
- 직급 이름(예: 주임, 대리, 과장, 차장, 부장)은 나중에 붙일 수 있게만 두고, M1에서는 표시하지 않습니다.

### 3.5 이미 만든 기반

M1 기능은 아래 기반 위에서 만듭니다.

- **신호 수집**: 앱이 `127.0.0.1`에 로컬 HTTP 서버를 열고, 앱을 켤 때 Claude Code와 Codex에 훅을 설치합니다. 훅이 보낸 이벤트는 renderer로 전달하고 디스크에 남기지 않습니다. 사용자가 원래 넣어 둔 훅은 건드리지 않습니다. 앱이 꺼져 있을 때 들어온 이벤트는 버립니다. 스펙: `openspec/specs/hook/spec.md`
- **에이전트 감지와 로그인 확인**: macOS, Windows, WSL 배포판마다 설치된 Claude Code와 Codex를 찾고 로그인 상태를 CLI에 묻습니다. 로그인은 사용자가 터미널에서 직접 합니다. 스펙: `openspec/specs/agent/spec.md`
- **시작 설정 창**: 에이전트, 모델, 로그인 확인을 단계별로 진행한 뒤 작은 3D 창으로 넘어갑니다. 스펙: `openspec/specs/start/spec.md`
- **작은 창**: 크기와 배치, 끌어 옮기기, 닫기. 스펙: `openspec/specs/window/spec.md`

확인한 사실은 다음과 같습니다.

- Claude Code 로그(`~/.claude/projects/<인코딩된 경로>/<세션>.jsonl`)의 `tool_use`와 `tool_result.is_error`는 믿을 수 있습니다.
- Codex 로그에는 도구 이벤트가 없어서 Codex는 훅으로만 신호를 받습니다. 이 Mac의 `codex-cli 0.131.0`은 훅을 쓸 수 있습니다(2026-11-04 기준).

## 4. M2 범위

M1이 끝난 뒤 디자인을 먼저 하고 정합니다. 지금은 후보만 적습니다.

- **연봉(LPA) 표시**: 레벨 대신 연봉으로 보여 줍니다.
- **직급 이름**: 레벨마다 붙일 직급입니다.
- **아이템 해금과 꾸미기**: 레벨이 오르면 옷, 책상, 방 아이템이 해금됩니다. 재화, 상점, 랜덤 상자는 넣지 않고, 아이템에 능력치 효과도 없습니다. 대신 파츠와 색상 변형으로 수를 늘립니다.
- **비주얼 업그레이드**: 방 확장, 소품 추가 등입니다.
- **직군 선택**: 플레이어가 직접 고르고 자동 판정은 하지 않습니다. 시작 옷과 소품, 대사, 직급 이름이 직군에 따라 달라집니다.
- **말풍선 대사**: 에러, 레벨 업, 오랜만의 작업 같은 순간에 힝글리시 대사를 잠깐 띄웁니다.
- **동시 세션 연출**: 세션이 여러 개일 때 캐릭터가 더 바빠 보이게 합니다. 모니터를 늘리거나 뒷모습을 보여 주는 방식은 쓰지 않습니다.

## 5. M1에서 정할 것

우선순위는 다음 기준으로 나눴습니다.

- **P0**: 정하지 않으면 그 기능의 스펙을 쓸 수 없습니다.
- **P1**: 스펙은 쓸 수 있지만 구현 중에 막힙니다.
- **P2**: 기본값으로 먼저 만들고 나중에 바꿔도 됩니다.

작업 상태 표시와 3D 모델링에서 정할 것은 `design/state-and-modeling.md`에 따로 정리합니다.

### 정하는 순서

P0끼리도 서로 기대는 것이 있어서 아래 순서를 권합니다.

1. 작업 상태 표시(`design/state-and-modeling.md`): 이미 받는 훅 이벤트만으로 만들 수 있어 가장 먼저 시작할 수 있습니다.
2. D-01, D-02, D-03: 경험치와 저장은 상태 표시와 같은 이벤트를 씁니다. D-03에서 정한 저장 위치를 퇴근 시각에도 씁니다.
3. D-05, D-06, D-07: 하루 정리 영상은 개인 정보와 CLI 실행이 걸려 있어 가장 오래 걸립니다. 확인할 일(Codex 로그, CLI 실행 시간)을 먼저 해 두면 좋습니다.
